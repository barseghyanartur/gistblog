dot-agents: code review, optimisation, and fix proofs

2026-10-09 | Tech | python, ai, agents, code-review, open-source

Since I first wrote about dot-agents, it has grown from six skills to nine. The new ones are all about reviewing code.

New skills

  • dot-agents-code-review reviews a pull request, branch, commit, or local changes for real bugs and security risks. Every finding needs evidence: where it breaks, how it gets triggered, and the smallest safe fix. If there's no evidence, it doesn't get reported.
  • dot-agents-code-optimisation does the same for performance, dead code, and duplication. It doesn't nitpick style.
  • dot-agents-reproduce-and-verify-fix turns a review finding into proof. It writes one small test with two cases. The first shows the bug failing in the real code. The second applies the proposed fix temporarily and runs the same checks again. You get the test, a short explanation, and a review comment ready to paste. It never changes your application code.

Clearer review output

Findings now use priorities from P0 (immediate) to P4 (lowest), based on the Google Issue Tracker scale. Each finding is numbered, says why it got its priority, and explains the fix properly. "Handle the error" isn't enough; it has to say which file to change, what to change, and why that works.

If the pull request links to a Jira ticket or another spec, the review checks each acceptance criterion and marks it as met, not met, or unverified.

Plain English everywhere

Every skill now asks the agent to explain things simply: main point first, short sentences, no inflated words. It also has to say what it checked and what it couldn't, instead of presenting guesses as facts.

Breaking change

All skills now start with dot-agents-, so /migrate-to-uv is now /dot-agents-migrate-to-uv. This avoids clashes with skills from other sources.

The repository is at github.com/barseghyanartur/dot-agents. MIT licensed.
